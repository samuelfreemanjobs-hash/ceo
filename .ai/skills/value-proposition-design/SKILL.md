# Value Proposition Design

A value proposition is the **bridge between positioning and persuasion**. It answers: "What outcome do I get, why should I believe you, and why you vs. alternatives?"

## Prerequisites

- Positioning statement approved (or draft with explicit gaps)
- ICP and switching trigger defined
- Alternatives named

## Value equation (diagnostic)

Score each dimension 1–5 for the proposed offer:

| Dimension | Question |
|-----------|----------|
| **Dream outcome** | How desirable is the end state? |
| **Perceived likelihood** | Will they believe it works for them? |
| **Time delay** | How fast do they get the outcome? |
| **Effort & sacrifice** | How hard is it to adopt? |

**Weak dimension → fix in offer architecture**, not copy padding. Low perceived likelihood → proof ladder. High effort → onboarding bonus or done-for-you layer.

## Structure

### Primary value prop (one paragraph)

Formula: **[Outcome]** for **[ICP]** without **[primary pain]** — **[differentiation mechanism]**.

- Lead with outcome, not product category
- Name the pain they recognize
- One differentiation mechanism (not a feature list)

### Supporting claims (max 3)

Each claim must map to:
1. A positioning pillar
2. A proof type (see ladder below)
3. A competitor contrast (implicit or explicit)

### Messaging hierarchy

| Level | Guidance |
|-------|----------|
| **Headline** | Outcome or contrast — 8 words or fewer ideal |
| **Subhead** | Mechanism + ICP specificity |
| **Proof bullets** | 3 bullets max — each a claim + evidence hint |
| **CTA direction** | Action that matches awareness level (learn / try / buy) |

Do not write full landing copy here — direction only. Copy-agent executes.

## Proof ladder (required)

| Claim | Proof type | Status | Notes |
|-------|------------|--------|-------|
| | Data / demo / social / guarantee / logic | Verified / Likely / Unverified | |

**Proof types:**
- **Data** — quantified outcome, benchmark, study (cite source or flag)
- **Demo** — product behavior they can verify in trial
- **Social** — logos, reviews, testimonials (permission required)
- **Guarantee** — risk reversal that makes claim credible
- **Logic** — structural argument (weakest; use sparingly)

**Status rules:**
- **Verified** — user provided evidence or public citable source
- **Likely** — reasonable inference from product structure; needs validation
- **Unverified** — aspirational; **must** flag for compliance-agent

## Evaluator loop (primary value prop)

1. Generate 3 variants: outcome-led, pain-led, contrast-led
2. Score each on: ICP specificity, believability, differentiation clarity
3. Refine winner; merge best elements if tied

## Anti-patterns

- Feature laundry list disguised as value prop
- Superlatives without proof ("best", "leading", "#1")
- Claims competitors could copy verbatim
- Outcome so grand it fails believability without proof ladder
- Skipping "who it's NOT for" in messaging implications

## Handoffs

- **To offer-architecture:** which claims need guarantee/bonus to become believable
- **To copy-agent:** messaging hierarchy + voice constraints
- **To compliance-agent:** all Unverified claims + competitive comparisons
