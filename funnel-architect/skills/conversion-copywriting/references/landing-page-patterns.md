# Landing page patterns

## Standard structure

```
Hero (headline + subhead + primary CTA + proof snippet)
→ Problem (agitate in customer's words)
→ Solution (mechanism, not feature list)
→ How it works (3 steps max)
→ Proof (logos, testimonials, metrics)
→ Objection handling (FAQ or comparison)
→ Final CTA (repeat primary action)
```

## Hero patterns

| Pattern | Example frame |
|---------|---------------|
| Outcome + timeframe | "Cut standup time 80% this week" |
| Audience call-out | "For EMs running 10–50 person teams" |
| Contrarian | "Your team doesn't need another meeting" |
| Risk reversal | "Try free — cancel if team won't adopt" |

## Above-the-fold requirements

- **One** primary CTA (not three equal buttons)
- Proof within one scroll (logo bar or stat)
- Mobile: headline readable without zoom

## BOFU comparison pages (`/vs/competitor`)

| Section | Content |
|---------|---------|
| Who each is for | Honest ICP fit |
| Feature table | 5–8 rows that matter |
| Migration / switch | Friction reducers |
| CTA | Trial or demo matched to motion |

## Pricing page

- Anchor recommended tier
- FAQ: billing, seats, security
- CTA per tier — same verb ("Start trial" not mixed verbs)

## Onboarding (in-product)

- Empty state = CTA + example output
- Progress indicator (3 steps max for activation)
- Force team invite if activation requires multi-user

## Evaluator (hero)

Run 3 variants → score on audience, promise, objection, CTA → ship strongest.
